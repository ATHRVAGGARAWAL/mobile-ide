# apps/mobile — implementation spec

Package `@mobile-ide/app`. Expo SDK 57, Expo Router, TypeScript strict, New Architecture (default). Targets: **ios** (primary) and **web** (secondary, must build with `npx expo export -p web`). No Android work needed but do not break it. Uses `@mobile-ide/core` for all types, the `MideClient`, and `applyEnvelope`.

Create the project with `npx create-expo-app@latest apps/mobile --template blank-typescript` (or equivalent) inside the pnpm workspace, then `npx expo install` the libraries below so versions match SDK 57. Set `"name": "@mobile-ide/app"`, add `"typecheck": "tsc --noEmit"`. Scheme `mobileide`. Bundle id `dev.mobileide.app`. Add `app.json` `web.output: "single"`, `web.bundler: "metro"`, and a PWA manifest (display standalone, theme colors) via `expo-router`'s `+html.tsx`.

## Libraries
expo-router, react-native-safe-area-context, react-native-screens, react-native-gesture-handler, react-native-reanimated, @shopify/flash-list, zustand, expo-secure-store (token on native; `localStorage` fallback on web behind one `storage.ts`), expo-haptics, expo-notifications (register Expo push token on native only; guarded so web builds), expo-clipboard, expo-image-picker (attach screenshots), @expo/vector-icons, react-native-keyboard-controller (native only; on web use `visualViewport`-driven padding — never trust `100dvh`), expo-web-browser, expo-linking. For DOM-only surfaces use Expo DOM components (`'use dom'` files): streaming markdown (`streamdown` or `react-markdown` + `remark-gfm`), unified diff view (`@git-diff-view/react` unified mode, or render from `oldText/newText` with the `diff` package), code viewer (`shiki` fine-grained: `shiki/core` + JS regex engine + ~12 languages), terminal (`@xterm/xterm` 6 + `@xterm/addon-webgl` + `@xterm/addon-fit`). Keep DOM components thin: props in, callbacks out (`useDOMImperativeHandle` not required).

## State (`src/state/`)
- `settings` store: `serverUrl`, `token`, `deviceId`, `serverName`, theme; persisted.
- `connection` store: one `MideClient` instance (from core) created on login; `ConnectionState`; exposes `client`.
- `sessions` store: `SessionSummary[]` (from REST + `sessions.changed`), `timelines: Record<sessionId, TimelineState>` (from `createTimeline`/`applyEnvelope`; call `client.subscribe(id, timeline.lastSeq)` when a chat screen mounts and keep subscriptions for sessions with pending permissions), pending permission inbox derived across sessions.
- `api.ts`: typed fetch wrapper over `core/API` with bearer header, zod-parsed responses, friendly errors.

## Screens (Expo Router, `app/`)
- `(auth)/pair.tsx` — Server URL field (prefilled from `?server=` / deep link `mobileide://pair?server=&code=` / URL fragment on web), pairing code field, device name; calls `POST /api/pair`; shows connection test result. On web, if opened in Safari (not standalone) show a banner: "Add to Home Screen first, then pair" (detect `display-mode: standalone`).
- `(tabs)/index.tsx` **Sessions** — header with server name + connection dot (green/amber/red with reconnecting label). Top section "Needs you" listing pending permissions across sessions (tap → opens the session with the sheet pre-opened). Then sessions grouped Running / Idle / Errored, each row: agent badge, title, project name, relative time, status chip, last message preview, unread indicator. Pull to refresh. FAB "New session" → `new-session.tsx` modal (agent picker with availability, project picker with recent + browse, optional title, mode picker, first prompt). Swipe actions: rename, close.
- `session/[id].tsx` **Chat** — FlashList (v2, `maintainVisibleContentPosition`) over `TimelineState.items`; item renderers: user bubble (right, with image thumbnails), assistant markdown (DOM component, streaming-safe, code blocks with copy), thought (collapsed "Thinking…" disclosure with char count), tool card (one-line collapsed: icon by `toolKind`, `describeTool()` label, status chip + duration; expands to raw input/output, diff content rendered by the unified diff DOM component, locations as chips that open the file viewer), plan card (checklist), permission card (inline "Needs your approval" with the full literal command/input, opens the bottom sheet), turn_end divider (stop reason + tokens/cost when present), error banner. Composer pinned above the keyboard: multiline input, `/` triggers slash-command suggestions from `timeline.commands`, `@` triggers file autocomplete via `/api/fs/search` (paths), attach image, send (disabled while disconnected; queue with "will send when reconnected" is fine), Stop button while running (calls `cancel`). Header: title (tap to rename), mode selector (`availableModes` → `set_mode`), agent badge, menu (Files, Changes, Terminal for this cwd; Close session). "Jump to latest" pill when scrolled up. Haptic on permission arrival and turn end (native).
- `permission-sheet` — bottom sheet listing: agent/tool title, kind icon, **the raw input verbatim in a monospace block** (command, path, or JSON), diff preview if present, buttons from `options` ordered allow_once, allow_always, reject_once, reject_always with distinct colors; allow_always shows a confirm step. Calls `respondPermission`; optimistic UI; retries on reconnect.
- `(tabs)/files.tsx` **Files** — project picker (from `/api/projects`), breadcrumb tree via `/api/fs/tree`, git status colored dots, search bar (`/api/fs/search`), tap file → `file.tsx` viewer (Shiki DOM component, line numbers, wrap toggle, share/copy, size/truncated notice, jump to line via `?line=`).
- `(tabs)/changes.tsx` **Changes** — `/api/git/status` list (staged/unstaged sections); tap → unified diff (DOM component) with per-file header; whole-tree diff toggle; recent commits from `/api/git/log`.
- `(tabs)/terminal.tsx` **Terminal** — lazy DOM component wrapping xterm over `/ws/terminal` (binary frames), accessory key row (Esc, Tab, Ctrl, ⌃C, ⌃D, ↑↓←→, `|`, `-`), cwd = selected project, reconnects with the same `id` so the tmux session persists. Fit on resize.
- `(tabs)/settings.tsx` — server/device info, connection state, notifications (native: register Expo push; web: Web Push subscribe when standalone; everyone: ntfy topic field → `/api/push/register`; "Send test"), theme, "Forget this server".

## Live filesystem and the Studio
- The file viewer watches its folder over the daemon socket (`fs.watch` → `fs.changed`, `src/lib/liveFs.ts`) and re-reads the file the moment an agent (or the Studio) writes it, flashing an "Updated just now" chip. Watches are per (root, dir), end with the screen, and are re-established by the client after a reconnect.
- Session menu → *Open in Studio* (`POST /api/studio/open`): the daemon pops the laptop's live editor following this session; the toast says whether a window opened, an existing one is following, or why nothing opened.

## UX rules
- Dark and light themes from one token file (`src/theme.ts`); system default. Large tap targets; monospace for code/commands; never truncate a command in the permission sheet.
- Every network action shows inline state (sending / failed with retry). Connection loss is a thin banner, not a modal.
- Mark items read per session (last seen seq) to drive unread badges.
- Deep links: `mobileide://session/<id>` and `/session/<id>` (web) — used by notification `Click` URLs.

## Verification for the build agent
`pnpm --filter @mobile-ide/app typecheck` passes; `npx expo export -p web` succeeds; `npx expo-doctor` passes or only warns. Do not attempt an iOS build. Provide `apps/mobile/README.md` with dev commands (`npx expo start --web`, `eas build -p ios --profile development`) and an `eas.json` with development/preview/production profiles.
